# Findings — 2026-08-10

Point-in-time snapshot from one run of the `model-discovery` pipeline against
a local gateway instance. Provider quota/balance state in particular will
have moved on by the time you read this; the methodology and the general
shape of the results (which providers are reliable, which need a
non-standard request shape) should still hold.

## Catalog

- `fetch_catalog.py`: 745 raw entries, 5 exact-id duplicates → **740 unique
  model ids**, across 37 gateway-provider prefixes. 11 prefix pairs turned
  out to expose an identical model list under two names (e.g. `ali`/`alibaba`,
  `kiro`/`kr`, `codex`/`cx`) → **26 actually-distinct backends**.

## Rating coverage (`match_aa.py` + `match_arena.py`)

- Artificial Analysis (Intelligence Index v4.1.1, free tier, 595 models):
  matched **381 of 740** ids to a real measured score.
- Of the 359 unmatched: 180 are non-text (image/video/audio/embedding —
  outside AA's scope by definition), 78 genuinely not found in either
  catalog, 44 rejected by hand (a similar-looking candidate existed but was
  a different version/size/tier — see match_aa.py's numeric-gate comment),
  36 are the gateway's own routing meta-endpoints (`auto/*`), not fixed
  models.
- Full Arena leaderboard (386 models) parsed from a saved page export;
  98 models overlapped with AA closely enough to calibrate against
  (isotonic regression, leave-one-out MAE ≈ 6.9 / RMSE ≈ 8.6 on AA's 0–65
  scale). Extended scored coverage to **~22 additional models** AA doesn't
  track (`+36` ids counting provider aliases).

## Live reachability (`smoke_test.py`)

579 of 740 ids are chat-completion-testable (rest need embeddings/audio/
image endpoints). Single pass, one retry only on a short provider-reported
cooldown:

| status | count | meaning |
|---|---:|---|
| answered | 291 | real 200 + content |
| quota/balance | 210 | provider-side, likely temporary (see below) |
| not tested | 161 | non-chat endpoint shape |
| broken | 78 | real 400/404/5xx/timeout right now |

Two whole providers were fully quota-exhausted for the entire run
(antigravity: daily reset; a `codex`-backed provider: reset measured in
hundreds of hours) — 100% "failure" there reflects account state, not the
integration. `dgrid` (144 models, second-largest single provider) hit a
shared-balance limit on ~95% of attempts, confirmed even with zero
concurrency (sequential requests still failed identically) — genuinely
exhausted right now, not an artifact of parallel probing.

Nine models across three providers (Mistral, Cerebras, one Groq model
family) initially looked broken and were false negatives from this
pipeline's own first-draft request: those backends reject an unrecognized
`reasoning` field with a 400/422 instead of ignoring it. Fixed by not
sending that field (current `smoke_test.py`/`tool_use_test.py` already
don't).

## Tool use (`tool_use_test.py`)

Tested the 291 reachable models with a real `tools` payload: **256 (88%)**
produced a correct `tool_calls` entry. 22 answered in plain text without
calling the tool, 7 had the request rejected outright, 4 called the tool
with a malformed/empty argument.

Prompt phrasing mattered more than expected: an earlier draft prompt
("...don't guess") got a *"which city?"* clarifying question back from
several models that clearly do support tool calling — they had the answer
already in the prompt and still asked. Rewriting to a blunt imperative
naming the literal argument value fixed most of these (pilot sample:
9/21 → 16/21 correct tool calls, same models, only the wording changed).

## Practical takeaway

Cross-referencing all three signals (rated + currently reachable + real
tool use) rather than trusting the `/v1/models` capability flags changed
the answer to "what's the best model I can use right now" quite a bit: the
highest-AA-scored models in the catalog were, at the time of this run, on
providers sitting at zero quota — so "best model available" and "best
model reachable" were two different lists. A downstream agent config
should pick primary/fallback models from the *reachable-and-tool-capable*
list, ordered by score, not from the raw score ranking alone.
